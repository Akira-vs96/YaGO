# YaGo

Учебный городской сервис для Астаны: такси, доставка еды из заведений и аренда электросамокатов. Интерфейс — React/Vite + Leaflet, API — FastAPI, данные — PostgreSQL/PostGIS. Заказы, сессии, статусы, тарифы и аренды сохраняются в БД. Велосипеды исключены из новых операций; старые записи остаются доступными как архив.

## Быстрый запуск с Docker

Нужны Docker Engine и Compose. Из чистого checkout:

```bash
docker compose up -d --build
docker compose exec api python seed_demo.py
```

Откройте http://localhost:8088. Проверка API: http://localhost:8008/api/health, OpenAPI: http://localhost:8008/docs. API запускается одним worker: WebSocket-рассылка хранится в памяти процесса. Миграции автоматически выполняются при старте API под PostgreSQL advisory lock. Отдельный seed безопасно повторять: он добавляет только отсутствующие демозаписи.

Compose использует отдельное имя проекта `yago-study`, volume БД и локальные порты 55433/8008/8088. Перед первым запуском можно скопировать корневой [.env.example](.env.example) в `.env`, изменить пароль и порты. После инициализации volume пароль PostgreSQL не меняется автоматически при изменении `.env`.

Демо-входы: `client@demo.yago.test`, `driver@demo.yago.test`, `courier@demo.yago.test`, `operator@demo.yago.test`, `admin@demo.yago.test`. Пароль по умолчанию: `YaGo-demo-2026!`; для другого пароля выполните `docker compose exec -e DEMO_PASSWORD=новый-пароль api python seed_demo.py` при первичном создании демоучётных записей. Это вымышленные данные. Демо-аккаунты и исторические примеры такси, доставки и аренды создаются только отдельной командой; повторный seed не сбрасывает пароли и не дублирует операции.

Для локального запуска API и интерфейса без Compose оставьте в Compose только PostgreSQL. В первом терминале:

```bash
docker compose up -d db
cp server/.env.example server/.env
cd server/fastapi
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8008
```

Во втором терминале из корня проекта:

```bash
npm ci
npm run dev
```

Frontend доступен на http://localhost:5173. Если меняли `POSTGRES_PASSWORD` для Compose, укажите тот же пароль в `DATABASE_URL` локального `server/.env`. Для создания демоданных из корня проекта используйте `server/fastapi/.venv/bin/python server/fastapi/seed_demo.py`; скрипт читает локальный `server/.env`. Основной путь демонстрации — Compose выше.

## Миграции и сохранность

SQL-миграции находятся в [server/fastapi/migrations](server/fastapi/migrations). Версии выполняются последовательно в транзакции. Для непустой базы при обновлении требуется резервная копия и `BACKUP_CONFIRMED=1`. Не удаляйте volume, чтобы «починить» схему.

```bash
docker compose exec -T db pg_dump -U yago -d yago -Fc > yago-backup.dump
# После проверки файла резервной копии:
BACKUP_CONFIRMED=1 docker compose up -d api
```

Восстановление выполняйте в отдельную пустую БД: `docker compose exec -T db createdb -U yago yago_restore`, затем `docker compose exec -T db pg_restore -U yago -d yago_restore --no-owner < yago-backup.dump`. Сверьте данные до переключения API на восстановленную базу. Для существующей незаверсионированной базы автоматическая миграция остановится: сначала сделайте backup и согласуйте её исходную схему.

Заказы хранят снимки адресов, координат и маршрута, заведения, цены и названия купленных блюд, доставки, скидки, итоговой суммы и ссылку на неизменяемую версию тарифа. Эти значения сохраняют исторический факт сделки, когда текущий каталог или адресная книга меняются. Схема, ключи и ER-диаграмма описаны в [docs/DATA_MODEL.md](docs/DATA_MODEL.md).

## Безопасность и роли

Регистрация выдаёт только роль клиента. Браузерная сессия — HttpOnly cookie; изменяющие запросы требуют CSRF-токен, передаваемый из отдельной cookie. Локальный HTTP использует `COOKIE_SECURE=0`; для HTTPS поставьте `COOKIE_SECURE=1`, укажите точный `CORS_ORIGINS` и сильный `POSTGRES_PASSWORD`. Пример HTTPS-прокси — [deploy/Caddyfile](deploy/Caddyfile), нужен реальный домен и открытые 80/443. Клиент видит свои операции, исполнитель — свои назначения, оператор — операционные данные, администратор — роли, аудит и журнал входов. Для непрерывной передачи координат исполнитель включает геотрекинг в кабинете и разрешает браузеру доступ к геопозиции.

Оплата и физическое открытие замка эмулируются; при `DEMO_MODE=1` владелец брони может получить учебный QR в интерфейсе. 2FA использует стандартный шестизначный код TOTP из приложения-аутентификатора. Студенческий статус проверяется учебным кодом только при `DEMO_MODE=1`; тогда сервер применяет скидку 10% к такси и доставке. При выключенном demo-режиме эта проверка и скидка отключены до подключения настоящего провайдера. Состояния, права, расчёты и запись данных выполняются настоящим API и PostgreSQL.

Публичные Nominatim и OSRM могут быть недоступны или ограничивать запросы; для развёртывания используйте собственные или согласованные endpoints и контактный User-Agent. Карта атрибутирует OpenStreetMap. OSRM используется только для автомобильных маршрутов такси и доставки; самокатный маршрут не заявляется. Автомобильный маршрут не подменяется выдуманной геометрией при ошибке провайдера.

Интеграционный сценарий [smoke_test.py](server/fastapi/smoke_test.py) создаёт и меняет данные, поэтому запускайте его только на отдельном учебном стенде: `docker compose exec -T api python smoke_test.py`. Он проверяет PostgreSQL/PostGIS, права, три услуги, повторы, конкуренцию, историю, TOTP, ближайшего исполнителя, версии тарифов и адресную приватность WebSocket. Клиентские проверки: `npm run lint`, `npm run build`.

Текущее состояние, проверки и оставшиеся задачи ведутся в [docs/IMPLEMENTATION_STATUS.md](docs/IMPLEMENTATION_STATUS.md). Старые материалы курса остаются в [TZ_15weeks_team_plan.md](TZ_15weeks_team_plan.md) как проектный архив и не являются инструкцией запуска.
