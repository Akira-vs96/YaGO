## Функциональная сверка

| Требование ТЗ | Результат |
| --- | --- |
| Регистрация, cookie-сессии, CSRF, роли и контроль HTTP/WebSocket | Реализовано. Ограничение ошибок входа хранится в PostgreSQL; TOTP работает через приложение-аутентификатор. |
| Такси и доставка еды | Реализованы каталог, серверный расчёт, назначение, статусы, история и отзыв. Для такси множитель спроса 1.25 применяется, когда ожидающих поездок не меньше числа свободных водителей (минимальный порог — одна). |
| Самокат | Реализованы бронь, QR-эмуляция, аренда, тарифный снимок, геозоны, завершение и операторские состояния. |
| Велосипед | Не реализован, хотя входит в раздел 2 исходного ТЗ. Услуга не показывается и новые заказы отклоняются ограничением БД. |
| Карта и трекинг | OSM/Nominatim/OSRM, WebSocket и восстановление через REST. Внешние сервисы и один API worker — эксплуатационные ограничения. |
| Администрирование и аналитика | Есть управление ролями/сессиями, тарифами, зонами и парком, аудит, заказы, выручка, ожидание и тепловая карта. |
| Схема и миграции | Версия 9; миграция `008_final_acceptance.sql` добавляет неизменяемый множитель спроса и таблицу попыток входа. |
| Демо-данные | 12 аккаунтов. Четыре клиента имеют разные такси, доставки, блюда, маршруты, даты и аренды; заведения распределены между операторами. Seed хранит эти примеры вне миграций и проверяет повторную вставку. |

## Проверки

Командный протокол в [комплекте недель 11–15](final/README.md) сообщает об успешных ESLint/build, интеграционном наборе, Chrome-репетиции, проверке аналитики на 10 000 дополнительных заказах и сравнении резервной копии с восстановленной БД.

В этой рабочей сессии подтверждены `git diff --check`, `npm run lint`, `npm run build` и Python compileall после интеграции. `docker info` не подключился к Docker daemon (`/var/run/docker.sock` отсутствует), поэтому миграции, `smoke_test.py`, browser rehearsal и restore script здесь не запускались. Они работают с БД и должны выполняться только на отдельной приёмочной базе.

## Что мешает заявить полное соответствие

1. Реализовать аренду велосипедов либо официально изменить ТЗ и проектные модели.
2. Завершить артефакты и согласование недель 1–7: реестр требований, словарь, контракты, трассировку и журнал решений.
3. Провести и зафиксировать независимую приёмку на чистом стенде, включая backup/restore и публичное HTTPS-развёртывание, если оно требуется.
4. Добавить дату, подписи участников и результат реальной защиты; отчёт о технической репетиции этого не заменяет.
