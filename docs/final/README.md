# YaGo · командная защита, недели 11–15

Учебный стенд в Астане проводит три операции от экрана клиента до записи в PostgreSQL: поездку, доставку еды и аренду электросамоката. Этот комплект сводит результаты пяти участников по [действующему ТЗ](../../TZ_15weeks_team_plan.md). Велосипеды остаются в проектных материалах и архиве. Границы реализованной версии зафиксированы в [README проекта](../../README.md).

## Что показать и сказать

Пояснительная записка объединяет исходную [постановку задачи и учебную экономическую модель](../week-02/p1/ru/01-organizational-economic.md), [функциональные потоки модуля аренды](../../п-4/week-03-dfd.md), [классификаторы](../../п-4/week-04-classification.md) и [физическую модель](../DATA_MODEL.md). Ниже приведены правила расчёта и результаты для версии, работающей на стенде. Проектное описание первых недель шире фактического набора услуг.

Откройте сайт в отдельных профилях браузера для клиента, оператора и исполнителя. Обычные вкладки одного профиля используют одну сессию. Для каждого входа добавьте к короткому имени ниже `@demo.yago.test`. Учебный пароль свежего стенда — `YaGo-demo-2026!`. Подготовьте свободный самокат, двух свободных водителей и курьера.

Для показа восстановления использовать браузерную репетицию ниже: она разрывает связь клиента, меняет статус у водителя и возвращает сеть. | «Маршрут строит OSRM. Положение исполнителя приходит по WebSocket. При восстановлении связи клиент запрашивает состояние по REST, поэтому пропущенное изменение появляется в той же карточке». |

Затем кликнуть по зелёной парковке вне красной зоны и завершить. В кабинете оператора перевести этот номер в «Обслуживание», затем «Заблокирован» и «Доступен». | «Сервер проверяет бронь, код и точку парковки. В запрещённой точке аренда продолжается. Для двух водителей используйте `driver` и `driver2`. Перед показом у первого в «Кабинете» передайте позицию в центре, у второго — дальнюю. Оформите заказ около центра. Для переключения спроса на чистом стенде с двумя свободными водителями оставьте две поездки в статусе ожидания и рассчитайте третью. Затем отмените ожидающие учебные заказы либо проведите их до завершения.

## Контрольные расчёты П‑3 и П‑4

* **Такси.** Базовые ставки свежего стенда — 500 ₸ за посадку и 120 ₸/км. Учебное правило спроса для такси: при числе ожидающих поездок не меньше числа свободных водителей (порог не ниже одного заказа) множитель равен 1,25, иначе 1. На контрольном маршруте 2,5 км обычная цена 800 ₸. При повышенном спросе — 1 000 ₸, для подтверждённого студента — 900 ₸. При оформлении сервер перепроверяет сумму. Изменение цены требует подтверждения нового расчёта.
* **Доставка.** Сумма строк корзины плюс базовая стоимость доставки и её ставка за километры. Для свежего тарифа доставки обе ставки нулевые. Один «Бешбармак» за 2 900 ₸ обходится студенту в 2 610 ₸. Изменение меню после заказа сохраняет цену в истории.
* **Самокат.** Базовый тариф 100 ₸ плюс 35 ₸ за каждую начатую минуту, минимум одна минута. Поездка длительностью 61 секунду стоит 170 ₸. Точка 51.135, 71.445 попадает в демо-зону запрета. Точка 51.128, 71.421 — разрешённая парковка. При наложении зон запрет имеет приоритет.

## Как повторить

**Протокол от 19 ноября 2026 года.** На локальном стенде PostgreSQL 18 с PostGIS и одним процессом FastAPI прошли сборка, ESLint, интеграционный набор и браузерная репетиция в Chrome. Проверены экран 390 × 844, учебный заказ с маршрутом от реального OSRM, доставка, отзыв, аренда, получение одного события каждым из 24 дополнительных подписчиков и восстановление статуса после разрыва WSS. После перезапуска API в базе остались все 7 заказов и 3 аренды, находившиеся в ней перед перезапуском. Отдельный тест добавил в транзакции 10 000 заказов, сверил показатели и откатил данные. В одном из прогонов два запроса аналитики заняли суммарно 9 мс. Это замер на данном ноутбуке.

| Замечание предварительной проверки | Ответственный | Что проверили после исправления |
|---|---|---|
| Одновременные попытки входа и перезапуск процесса могли сбросить счётчик ошибок | П‑1 | База хранит ошибки по хешу почты. Пятая ошибка учитывается, шестой запрос получает 429, администратор видит событие |

1. Поднимите проект и загрузите учебные данные по [инструкции запуска](../../README.md). Для интеграционных тестов используйте отдельную БД. В каталоге `server/fastapi` с установленными зависимостями, `DEMO_MODE=1` и `DATABASE_URL` этой базы выполните `python seed_demo.py`, затем `python smoke_test.py`. Этот тест добавляет записи и меняет учебный каталог. Для контрольных сумм он задаёт маршрут длиной 2 500 метров. Нагрузочные строки аналитики откатываются после проверки.
2. Для локального HTTPS соберите интерфейс командой `npm run build --workspace src`. Запустите API на 8008 с `COOKIE_SECURE=1` и `CORS_ORIGINS=https://localhost:8443,https://127.0.0.1:8443`. Из корня проекта выполните `caddy run --config deploy/Caddyfile.local --adapter caddyfile`. Этот профиль слушает loopback и выпускает сертификат локального центра Caddy. Браузер без доверия к этому центру покажет предупреждение. Публичный адрес требует домена и отдельного развёртывания.
3. На подготовленном стенде с исходными демо-тарифами освободите обоих водителей, курьера и YG-101. Установите зависимости проекта (`npm ci`) и Chrome. Выполните `node scripts/rehearse-team.cjs`. Адрес по умолчанию — `https://localhost:8443`; для другого локального адреса задайте `YAGO_URL`. Репетиция создаёт отдельного клиента, проводит реальные учебные заказы через сайт и оставляет их в истории. Адресный сервис и маршрутизатор доступны по сети; браузер использует доверие к локальному тестовому сертификату только в своих тестовых контекстах.
4. Для проверки резервной копии используйте PostgreSQL CLI с соединением к остановленной для записи тестовой базе. Задайте `PGHOST`, `PGPORT`, `PGUSER`, `PGDATABASE` и выполните из корня `sh scripts/check-restore.sh`. Команда создаёт отдельную БД и выводит путь к архиву. Роли PostgreSQL нужны права на создание БД и расширения PostGIS. Архивы содержат данные аккаунтов и хранятся вне Git.

## Схемы и границы демонстрации

* [Архитектура стенда](architecture.svg) и [редактируемая схема](architecture.mmd). Адреса ищет Nominatim, дорожный маршрут считает OSRM, тайлы отдаёт OpenStreetMap. При сбое обратного поиска выбранные координаты остаются пригодны для расчёта. При недоступности маршрутизатора интерфейс сообщает об ошибке.
* [ER-диаграмма для записки](er-model.svg) и [исходная модель со словарём](../DATA_MODEL.md). Заказ хранит измеренные факты сделки; состояния аренды ведутся отдельно. PostGIS проверяет принадлежность точки парковке.
* Студенческий статус подтверждается учебным кодом, замок отвечает на демо-QR, платежи записываются внутри сервиса. Коды 2FA генерирует приложение TOTP. Демонстрационные позиции водителей выбираются явно. Трек реального устройства требует разрешения браузера.
* Проверенный стенд работает на ноутбуке с одним процессом API. Проход в Chrome подтверждает техническую репетицию. Дату выступления, замечания комиссии и решение о зачёте фиксирует команда после защиты.
