# Обзор исходного проекта YaGo

[Все материалы недели](../../README.md) · [Қазақша](../kk/00-project-review.md)

Дата: 24.09.2026. Основание: все собственные исходники, конфигурация, manifests и lock-файл проекта, README и [ТЗ](../../../../TZ_13weeks_team_plan.md). Сторонний код `node_modules` и сгенерированный `dist` не являются предметом проектирования. Это состояние прототипа **до реализации следующих недель**, а не описание готового продукта.

## 1. Состав и исполнение

| Файл | Назначение и фактическое использование |
|---|---|
| `package.json`, `package-lock.json` | npm workspaces `server` и `src`; совместный запуск через concurrently, сборка двух workspaces, lint только frontend |
| `.gitignore` | Исключает зависимости, `.env`, сборки и npm-логи; каталог `.git` в переданной рабочей папке отсутствует |
| `server/package.json` | Node.js ESM, Express 4, Socket.IO 4, `pg`, dotenv; backend build выводит сообщение, компиляции или проверки типов нет |
| `server/src/index.js` | Реальная точка входа: HTTP API, Socket.IO, встроенные массивы данных, Pool PostgreSQL |
| `server/src/config.js` | Заготовка конфигурации; точка входа её не импортирует. Поэтому `CITY` из `.env.example` фактически не меняет город API |
| `server/src/data/mockData.js` | Отдельная копия демоданных; сервер её не импортирует |
| `server/src/modules/orderService.js` | Заготовка операций с заказами и исполнителями; импортирует `mockData.js`, но HTTP-сервер её не использует |
| `server/.env.example` | Пример PORT, DATABASE_URL, CITY. Настоящих учётных данных в примере нет |
| `src/package.json`, `src/vite.config.js` | React 18, Vite 5, Leaflet, react-leaflet, socket.io-client; dev proxy `/api` и `/socket.io` на порт 4000 |
| `src/index.html` | HTML, шрифт с Google Fonts, CSS Leaflet с CDN |
| `src/main.jsx` | Монтирование React StrictMode и подключение CSS |
| `src/App.jsx` | Весь интерфейс, REST-запросы, обработчики событий, форма заказа, карта, каталог и показатели |
| `src/styles.css` | Стили и адаптивные сетки для desktop/mobile |
| `README.md`, `TZ_13weeks_team_plan.md` | Инструкции запуска и план развития; перечисленные бизнес-сценарии шире текущей реализации |

`npm run dev` запускает два процесса. Браузер обращается к Vite на `:5173`; прокси направляет REST и Socket.IO в Express на `:4000`. API содержит три ресторана, девять блюд, трёх исполнителей (включая водителя) и два начальных заказа. Изменения живут в памяти процесса и исчезают после перезапуска. `pg` используется только внутри проверки здоровья: `SELECT 1`; таблиц, миграций и записи заказов в PostgreSQL нет.

## 2. Реальные контракты API

| Метод и путь | Текущее поведение |
|---|---|
| `GET /api/health` | Проверяет соединение с PostgreSQL; при ошибке всё равно отвечает HTTP 200, `ok: true`, `db: offline-demo` и текстом ошибки |
| `GET /api/config` | Название, город, центр, список ролей и строковые feature flags; список не проверяет наличие модулей |
| `GET /api/restaurants` | Рестораны с вложенным `menu` |
| `GET /api/orders` | Все заказы, без фильтрации по клиенту |
| `GET /api/couriers` | Общий массив курьеров и водителя |
| `POST /api/orders` | Добавляет заказ, возвращает HTTP 201, рассылает `orderCreated`; есть значения по умолчанию |
| `POST /api/orders/:id/status` | Устанавливает переданную строку статуса, рассылает `orderStatusUpdated`; 404 при отсутствии заказа |
| `POST /api/trace` | Меняет координаты указанного исполнителя, рассылает `driverMoved`; 404 при отсутствии исполнителя |

При Socket.IO-подключении сервер отправляет `welcome`. Входящее событие `joinRoom` вступает в произвольную комнату, но текущие изменения отправляются всем через `io.emit`, а не в комнаты. Источником перемещения служит ручной POST `/api/trace`; GPS-устройство и автоматический симулятор не подключены.

## 3. Что показывает интерфейс

Карта Leaflet отображает тайлы OpenStreetMap, рестораны, исполнителей и прямые отрезки между `start` и `end` заказов. Эти отрезки не являются дорожными маршрутами. Форма создаёт `food` или `taxi`, передавая имя клиента, ресторан, координаты и цену с клиента. Поле ресторана передаётся даже для такси.

Кнопки «Главная», «Еда», «Такси», «Админка» меняют `selectedTab` и выделение кнопки, но не состав страницы. Корзины, оплаты, регистрации, настоящей админ-панели, оценок и истории по пользователю нет. Надпись `Live` постоянна и не отражает состояние соединения. «Активные заказы» показывает длину всего массива, «Курьеры онлайн» считает всех `available`, включая водителя, а время доставки задано текстом.

## 4. Расхождения и дальнейшие действия

| Наблюдение по коду | Последствие | Место в плане |
|---|---|---|
| Express и Leaflet вместо NestJS/2ГИС | Нужен явный переход к стеку ТЗ | Архитектурное решение недели 2; реализация недель 3–5 |
| Данные и функции дублируются вне точки входа | Изменение `orderService.js` сейчас не меняет API; значения `end` уже расходятся | Объединение логики при каркасе недели 3 |
| Пользователь — строка `customer`; роли — список строк | Нет идентификации, сессий, ограничений доступа | Недели 4–6 |
| `food` — тип заказа, `couriers` содержит и водителей | Нужно согласование общей модели такси/доставки/аренды | [Сущности](../../p3/ru/03-database-entities.md) и [ER-модель](../../p5/ru/05-er-model.md) |
| Нет хранения заказов, тарифов, зон, техники | PostgreSQL-конфигурация не означает реализованную БД | Недели 3–5 |
| Цена, исполнитель и статус принимаются без проверки; ID на `Date.now()` | Нельзя обеспечить корректный расчёт, переходы статусов и уникальность при конкуренции | Недели 4–6, аудит недели 10 |
| Созданный заказ добавляется и по HTTP-ответу, и по Socket.IO | У инициатора возможно дублирование одного заказа | Интеграция недели 7: обновление по ID |
| Все события рассылаются всем, `joinRoom` без проверки прав, CORS открыт | Нет разграничения видимости заказов и координат | RBAC/трекинг недели 6, аудит недели 10 |
| SSL `rejectUnauthorized: false`; health отдаёт внутреннюю ошибку | Конфигурация соединения и диагностики требует пересмотра перед размещением | Недели 10–11 |
| Нет resync после пропущенных событий | Карта может остаться устаревшей после переподключения | Неделя 9 |
| `scooter_tracking` есть лишь в feature flags | Аренда самокатов не реализована | Спецификация недели 2; недели 5–8 |
| `npm start` поднимает только API; статика не раздаётся | Одна сборка frontend ещё не даёт работающий production-сайт | Размещение frontend и reverse proxy недели 11 |

Это перечень входных данных для архитектуры, а не заявление о выполнении последующих недель. Изменение поведения приложения во второй неделе не требуется.

## 5. Проверка исходного состояния

Проверено 24.09.2026, Node.js `v20.19.2`, npm `9.2.0`, с установленными зависимостями:

| Проверка | Результат и предел проверки |
|---|---|
| `npm run build` | Успех: frontend собирается; backend-скрипт только выводит сообщение |
| `npm run lint` | Ошибка до анализа кода: ESLint 9 не находит `eslint.config.js/mjs/cjs`; такой конфигурации в исходном проекте нет |
| Изолированный запуск API | Успех: каталог 3×3, 2 начальных заказа, 3 исполнителя, создание и изменение заказа, обновление координат, ответы 404 для неизвестных ID |
| Socket.IO на изолированном API | Получены `welcome`, `orderCreated`, `orderStatusUpdated`, `driverMoved` |
| Health без внешней БД | Проверен `offline-demo`: для временного процесса задан недоступный локальный DATABASE_URL; внешняя БД не использовалась |

Временный API остановлен после проверки. Эти проверки подтверждают поведение демонстрационного backend, но не проверяют полноценные пользовательские сценарии, работоспособность внешней БД, авторизацию или браузерный интерфейс. В исходных npm scripts команды `test` нет.
