# 12-апта — YaGo жүйесін кешенді қабылдау сценарийлері

Бұл құжат клиент, орындаушы, оператор және әкімші рөлдерімен жүйенің негізгі жұмыс жолдарын басынан аяғына дейін тексеруге арналған. Сынақтарды демо деректері бар бөлек оқу ортасында орындаңыз: тапсырыс, бронь және тариф құру дерекқорды өзгертеді.

## Дайындық

| № | Дайындық қадамы |
|---|---|
| 1 | Қосымшаны түбірдегі [README нұсқаулығына](../../README.md) сай іске қосып, демо деректерін дайындаңыз. |
| 2 | Клиент, орындаушы, оператор және әкімші аккаунттары үшін бөлек браузер терезелерін не профильдерін пайдаланыңыз. Демо логиндер негізгі README файлында берілген. |
| 3 | WebSocket тексеру үшін жүйеге кіріңіз. Браузердің Developer Tools → **Network** → **WS** бөлімін ашып, бетті жаңартыңыз. Авторизацияланған кезде `/ws` қосылымы ашылуы керек. |
| 4 | Әр тексерудің нәтижесін төмендегі тіркеу кестесіне енгізіңіз. Сәйкессіздік табылса, дефект кестесін толтырыңыз. |

## Нәтиже мен HTTP кодтарын түсіндіру

| Белгі/код | Мағынасы |
|---|---|
| **PASS — өтті** | Нақты нәтиже күтілген нәтижеге сәйкес. |
| **FAIL — өтпеді** | Нәтиже күтілгеннен өзгеше; дефект тіркеу керек. |
| **BLOCKED — бөгелді** | Ортаның немесе басқа ақаудың салдарынан тексеру орындалмады. Себебін жазыңыз. |
| HTTP `200` / `201` | Сұрау сәтті орындалды / жаңа жазба құрылды. |
| HTTP `401` | Пайдаланушы жүйеге кірмеген. |
| HTTP `403` | Жүйеге кірген, бірақ бұл әрекетке құқығы жоқ. |
| HTTP `404` | Нысан табылмады немесе осы пайдаланушыға қолжетімсіз. |
| HTTP `409` | Әрекет ағымдағы күйге қайшы келеді. |

## 0-сценарий — жүйеге кіру және негізгі құқықтар

| Қадам | Рөл | Әрекет | Күтілетін нәтиже |
|---|---|---|---|
| 0.1 | Жүйеге кірмеген | `/api/auth/me` бетін ашу | HTTP `401` қайтарылады. |
| 0.2 | Әр рөл | Интерфейске кіріп, өз кабинетін ашу | Кіру сәтті; тиісті пайдаланушы көрсетіледі. |
| 0.3 | Клиент | `/api/admin/users` әкімшілік тізімін ашу | HTTP `403`; пайдаланушылардың деректері ашылмайды. |
| 0.4 | Орындаушы | `/api/admin/analytics` аналитикасын ашу | HTTP `403`. |
| 0.5 | Оператор | `/api/admin/users` әкімшілік тізімін ашу | HTTP `403`. |
| 0.6 | Әкімші | `/api/admin/users`, `/api/admin/audit` және `/api/admin/analytics` ашу | HTTP `200`; деректер қолжетімді. |
| 0.7 | Клиент | CSRF токенінсіз профильді өзгертуді сұрау, кейін сол әрекетті интерфейстен орындау | Токенсіз сұрау HTTP `403`; интерфейстегі сұрау сәтті өтеді. |

## 1-сценарий — такси тапсырысын рәсімдеуден аяқтауға дейін тексеру

| Қадам | Рөл | Әрекет | Күтілетін нәтиже |
|---|---|---|---|
| 1.1 | Клиент | Таксиді таңдап, басталу және баратын нүктелерді енгізіп, бағаны есептеу | Маршрут пен сервер есептеген баға көрсетіледі. |
| 1.2 | Клиент | Тапсырыс жасау | Тапсырыс күту күйінде құрылады және клиент тарихында көрінеді. |
| 1.3 | Басқа клиент | Тапсырысты идентификаторы арқылы ашу | HTTP `404`; басқа клиенттің деректері көрсетілмейді. |
| 1.4 | Оператор | Жаңа тапсырысты тауып, орындаушы тағайындау | Орындаушы тағайындалып, тапсырыс күйі «тағайындалды» болады. |
| 1.5 | Клиент, орындаушы, оператор | Network → WS бөлімінде тапсырыс күйінің жаңаруын бақылау | Авторизацияланған `/ws` қосылымдары ашық; тапсырысқа қатысы бар пайдаланушылар жаңарту оқиғасын алады. |
| 1.6 | Орындаушы | Күйлерді ретімен өзгерту: «қабылданды», «келіп жатыр», «орындалуда», «аяқталды» | Рұқсат етілген әр ауысу сақталып, тапсырыс аяқталады. |
| 1.7 | Клиент | Бетті жаңартып, тапсырыс мәліметін қайта ашу | Соңғы күйі мен тарихы сақталған; маршрут пен баға көрсетіледі. |
| 1.8 | Басқа клиент | Бөгде тапсырыс туралы дерек алуға тырысу | WebSocket арқылы бөгде тапсырыс оқиғасы келмейді; HTTP сұрауы `404` қайтарады. |

**Ескерту:** орындаушы тек өзіне тағайындалған тапсырыстың күйін өзгерте алады. Бос орындаушы болмаса, тағайындау сәтсіз аяқталуы тиіс.

## 2-сценарий — тамақ жеткізу тапсырысы

| Қадам | Рөл | Әрекет | Күтілетін нәтиже |
|---|---|---|---|
| 2.1 | Клиент | Мейрамхана мен тағам таңдап, бағаны есептеу және тапсырыс рәсімдеу | Тапсырыс құрылады; сома сервер есептеген мәнге сәйкес. |
| 2.2 | Оператор | Тапсырысты «дайындалуда» күйіне, кейін «тағайындалды» күйіне ауыстыру | Екі ауысу да сәтті; курьер тапсырысқа бекітіледі. |
| 2.3 | Курьер | Тапсырысты қабылдау, алып кеткенін белгілеу және жеткізуді аяқтау | Күйлер ретімен өзгеріп, тапсырыс аяқталады. |
| 2.4 | Клиент | Тапсырыс тарихы мен мәліметін ашу | Соңғы күйі, тағам және сатып алу сәтіндегі баға көрсетіледі. |
| 2.5 | Клиент | Өзгенің немесе аяқталмаған тапсырысқа пікір қалдыруға тырысу | Пікір тек өзінің аяқталған тапсырысына қабылданады; қалған сұраулар қабылданбайды. |

## 3-сценарий — самокатты жалға алу

| Қадам | Рөл | Әрекет | Күтілетін нәтиже |
|---|---|---|---|
| 3.1 | Клиент | Картадан қолжетімді самокатты таңдап, брондау | Бронь құрылады. |
| 3.2 | Клиент | Өз бронінің демо-QR кодын алып, жалға алуды бастау | Жалға алу басталады; қолданылатын тариф нұсқасы бекітіледі. |
| 3.3 | Клиент | Геозонадан тыс жерде жалға алуды аяқтап көру | HTTP `409`; жалға алу белсенді күйде қалады. |
| 3.4 | Клиент | Рұқсат етілген тұрақ аймағында жалға алуды аяқтау | Жалға алу аяқталады; төлем сомасы бекітілген тарифпен есептеледі. |
| 3.5 | Екінші клиент | Сол самокатты бір уақытта брондауға тырысу | Тек бір бронь сәтті; екінші сұрау HTTP `409` алады. |
| 3.6 | Оператор | Самокатты техникалық қызмет күйіне ауыстыру | Өзгеріс сақталады; самокатты жалға алу мүмкін болмайды. |

## 4-сценарий — оператордың басқару әрекеттері

| Қадам | Рөл | Әрекет | Күтілетін нәтиже |
|---|---|---|---|
| 4.1 | Оператор | Тарифтерді, аймақтарды және техниканы басқару бөлімдерін ашу | Операциялық деректер қолжетімді. |
| 4.2 | Оператор | Оқшауланған стендте бірегей атаумен тест тарифін не аймағын құру, өзгерту және жою | Әрекеттер сәтті; өзгерістер тізімде көрінеді. |
| 4.3 | Клиент | Операторға арналған маршрут арқылы тарифті не аймақты өзгертуге тырысу | HTTP `403`; деректер өзгермейді. |
| 4.4 | Оператор | Әкімшіге арналған пайдаланушыларды басқару бетін ашу | HTTP `403`. |

## 5-сценарий — әкімші және аудит

| Қадам | Рөл | Әрекет | Күтілетін нәтиже |
|---|---|---|---|
| 5.1 | Әкімші | Пайдаланушылар тізімін және кіру/аудит журналдарын ашу | HTTP `200`; қолжетімді деректер көрсетіледі. |
| 5.2 | Әкімші | Аналитика мен жылу картасын ашу | Көрсеткіштер жүктеледі; координат деректері болса жылу картасы көрінеді. |
| 5.3 | Әкімші | Тест аккаунтының рөлін өзгертіп, нәтижені тексеру және бастапқы рөлін қалпына келтіру | Рөл өзгерісі сақталады; әкімші өзіндегі әкімші рөлін алып тастай алмайды. |
| 5.4 | Клиент немесе оператор | Әкімші маршрутын ашу | HTTP `403`. |

## 6-сценарий — WebSocket байланысын қабылдау

| Қадам | Рөл | Әрекет | Күтілетін нәтиже |
|---|---|---|---|
| 6.1 | Кез келген рөл | Жүйеге кіріп, Network → WS бөлімінен `/ws` қосылымын тексеру | Байланыс ашық; бастапқы келісу коды `101 Switching Protocols`. |
| 6.2 | Жүйеге кірмеген пайдаланушы | Авторизациясыз `/ws` ашып көру | Сервер WebSocket байланысын қабылдамайды. |
| 6.3 | Клиент пен орындаушы | 1-сценарийдегі тапсырыс күйін өзгерту | Тапсырысқа қатысы бар пайдаланушылар жаңарту оқиғасын алады. |
| 6.4 | Қатысы жоқ клиент | Сол оқиға кезінде WebSocket хабарламаларын бақылау | Бөгде тапсырыс туралы хабарлама келмейді. |
| 6.5 | Клиент | API-ді тоқтатып, сайтты ашық қалдыру; API қайта іске қосылған соң байланысты бақылау | Сайт қайта қосылып, REST арқылы өзекті деректі қайта жүктейді. |

Браузердегі WebSocket хабарламаларын көру үшін Network бөлімінен `/ws` жолын таңдап, **Messages** немесе **Frames** қойындысын ашыңыз. Демо хабарламада `event` өрісі мен тапсырыс деректері болуы мүмкін; құпия деректерді скриншотқа енгізбеңіз.
